## 4. 分割ロードマップ(2026-07-02 議論で改訂)

方針: **「マスタモデルの正は misarta」に寄せる**。当初の `articara-rbd` /
`articara-formats` 新設案は取り下げ(経緯は §4.4)。misarta には計算用
`Model<f64>` に加えて名前ベース・ロスレスの `native::MisaFile`(マスタ
スキーマ)が既にあり、編集操作の不変条件(rename 時の joint/mimic/
collision_pair/sensor/actuator/pose 追従更新)はスキーマ所有者の責務。
articara の `RobotModel` はマスタから **GUI ビューモデル**に降格する。

### 4.4 取り下げた案と経緯

`articara-rbd`(RobotModel + 編集 + 動力学の独立クレート)を当初提案したが、
検討の結果取り下げ。理由: (1) 静的動力学は既に misarta への薄いアダプタで、
独立させる実体がない。(2) 編集 API の自然な基盤は計算用 `Model` ではなく
misarta が既に持つ `native::MisaFile` であり、新クレートを挟むと
「マスタ表現の所有者」が二重になる。`articara-formats` も同根で、A4/A5
(misarta へ統合)に一本化。

### 4.6 A2 委譲方式の決定(2026-07-04 設計相談で確定)

素朴な「編集のたびに RobotModel → MisaFile 往復」は未保存 in-memory
メッシュを失うため不可、という発見を受けて3案を比較し、**案B
(EditTables visitor trait)を採用**。MisaFile 常駐 view-model 化(案C)は
「プロパティ変更・毎フレーム q 更新との同期面が巨大、保存時マージ問題」
のため**棄却**。

- misarta::native::edit を `EditTables` trait 上の汎用コア
  (`rename_link_in` / `rename_joint_in` / `remove_link_in`)に分解済み
  (misarta 4301a36)。MisaFile と articara `RobotModel` が同じ trait を
  実装し、**参照追従の不変条件は実装1つ**になる。
- 仕上げとしてパリティテスト(両経路の結果 MisaFile 一致を CI 検証)を
  articara に追加(案A を保険として併用)。
- **A4/A5 の前提も「常駐 doc」ではなく境界変換で足りる**:
  エクスポートは `build_misa_file()` → `misarta::mjcf::export(&MisaFile, …)`、
  インポートは misarta が MisaFile を返し既存 misa_load 経路で
  RobotModel 化。未保存メッシュは既存の materialize 手順で供給。

### 4.7 A4/A5 の置き場所と MJCF スコープ(2026-07-04 確定)

**置き場所**: misarta リポを workspace 化し、**`misarta-formats`**
クレートを新設(db741d0)。理由: フォーマット変換はエディタ都合で
高頻度に変わるため、コアと同居させると「MJCF の1行修正で全消費者の
misarta rev が動く」= 版ズレ事故の表面積が増える。新リポは作らない
(push サイクルと管理対象を増やさない)。articara は同一 git URL から
package 指定で取得。

**境界線**: ロボット記述形式(URDF/SDF/MJCF/USD)= formats。
`.misa`(マスタ)とメッシュ形式 I/O(STL/OBJ/DAE)= misarta 本体
(DAE は native::mesh_load が使うため、外に出すと逆依存になる)。
既存の misarta::urdf / sdf も A5 で formats へ移動(外部消費者ゼロ確認
済み、shim 不要)。

**MJCF(A4)手順**:
1. `misarta_formats::mjcf::import(path) -> MisaFile(+report)` —
   articara mjcf.rs のパーサ(~1,000行)を MisaFile 出力に移植
2. `misarta_formats::mjcf::export(&MisaFile) -> String` — 同様に
   エクスポータを移植(actuator/physics は schema が既に保持)
3. articara 側: import = formats 呼び出し + `misa_load::build_robot_model`
   再利用、export = `build_misa_file` → formats。既存 regression の
   MJCF テスト群がそのまま両経路の回帰網になる
4. USD / SDF(A5)は MJCF の型が固まってから同型で

**A5 実施結果(2026-07-04)**: misarta 4fd4ad8。
- **移動**: misarta::urdf / sdf(`Model<f64>` 直行ローダ)を loader テスト・
  fixture ごと misarta-formats へ機械移動。コアは .misa + メッシュ I/O のみに。
  消費者は misarta-py だけ(`misarta_formats::urdf` に切替済み)。
- **SDF**: articara sdf.rs (786行) を `misarta_formats::sdf::{import,export}`
  (MisaFile) に移植、articara は 90行の shim に。メッシュ `<uri>` は import 時に
  SDF-dir 相対へ正規化(`package://pkg/rel` → `../rel`、`model://x` → `x`)し、
  既存 misa_load のメッシュ解決をそのまま利用。ball joint は warning 付き
  Floating 近似。
- **USD**: usd.rs + usd_import.rs (計2,084行) を `misarta_formats::usd` に移植、
  articara は 計605行(大半は既存 round-trip テスト)の shim に。スキーマ外データは境界を明示: export は
  `UsdExportRefs`(posed FK transform / メッシュ頂点のコールバック、既定は
  q=0 チェーン)、import はインラインメッシュを sentinel + side-band で返し
  articara が RobotModel に再装着。忠実度向上: Capsule prim round-trip
  (旧 import は box 化)、`physics:filteredPairs` ⇄ collision_pair。
- 副作用として B1 由来の既存バグ発見: legged-estimation の approx
  dev-dependency 漏れ(lib test がコンパイル不能)→ 修正。

**A4 実施結果(2026-07-04)**: misarta fca26d9 で
`misarta_formats::mjcf::{import, import_str, export}` 実装済み
(単体+round-trip 12テスト)。articara mjcf.rs は 1,838→約280行の
境界層に縮小: auto-lift(`compute_min_z` はロード済みメッシュ依存)と
`MeshPathStyle` 適用(`source_path` 依存)だけを残し、mesh URI は
`MisaFile` に書き込んでから formats に渡す(formats は verbatim 出力)。
移植時に import の既存バグ2件を修正: `fullinertia` の読み順が MuJoCo
仕様(`Ixx Iyy Izz Ixy Ixz Iyz`)と不一致、`euler` 属性が
`angle="degree"` を無視。忠実度向上: asset `scale=` / actuator `gear=` /
geom インライン contact physics / `<contact><exclude>` を import で保持、
export で geom origin の回転を quat 出力(従来は黙って破棄)。
挙動変更: MJCF の free/ball joint は `joint_type` 文字列 "free"/"ball"
ではなく JointKind::Floating として入る(ball は warning 付き近似)。
regression 257 + lib 489 + Go2 実モデル import/export で検証済み。
