## 2. ArticaraApp 分割の進捗とパターン

**パターン**: 凝集フィールド群を「それを描画するパネルモジュール所有の
state 構造体」へ移し、`ArticaraApp` には1フィールドだけ残す。
`Default` impl に初期値を移し、参照は `self.<group>.<field>` に機械置換。
1グループ = 1コミット。

| グループ | フィールド数 | 状態 |
|---|---|---|
| `PeaksPlotState`(peaks_plot_window.rs) | 11 | ✅ |
| `GaitPanelState`(gait_panel.rs) | 24 | ✅ |
| `IkState`(mod.rs 内、横断状態) | 15 | ✅ |
| `DialogState` or 各パネルへ分配(`dlg_*` 残り7) | 7 | ⬜ |
| `ScriptConsoleState`(`script_*`) | 8 | ⬜ |
| `SimState`(`dynamics_sim` / `mujoco_sim` / `wbc_pipeline` / 推定器 / `ext_*` / `sim_drag_*`) | ~20 | ⬜ **cfg(mujoco) 81箇所の封じ込め先** |
| `ViewState`(camera ×3 / renderer / 表示モード / ground plane) | ~15 | ⬜ |

`cfg`)の実害を減らす主手段でもある。

## 4. クレート分離ロードマップ(汎用部分の外出し)

方針: quadruped-gait / misarta の先行例に倣い、「GUI 非依存の汎用ロジックは
独立クレート化して articara は消費者になる」。1-2a(bin の lib 消費者化)は
この下準備で、GUI ↔ コアの依存方向は既に一方通行。

| 候補 | 中身 | 依存 | 判断 |
|---|---|---|---|
| **`articara-rbd`**(仮) | `rbd/`(model + misarta_bridge + dynamics)+ robot.rs のデータ/編集部 | misarta, nalgebra | rbd/mod.rs の docstring が当初から想定。**formats 分離の前提**。`VisualData.color` 等の表示属性をどう扱うか(そのまま持つ/ジェネリック化)だけ設計判断が要る |
| **`articara-formats`**(仮) | mjcf / sdf / usd / usd_import / format(registry)/ mesh_paths | articara-rbd | 1-1 で registry 一本化済みなので切り出しやすい。refactor_20260502 §7.3 の「misarta へ移動」案との二択 — misarta を肥大させないなら独立クレート推奨 |
| **`legged-estimation`**(仮) | estimator/(18-state LKF + pipeline)+ attitude_estimator + leg_odometry | nalgebra, quadruped-gait(leg_odometry のみ) | 結合が薄く**最初に切り出しやすい**。go2-gait-runner が実機推定で直接使える実益あり |
| **mesh_ops → misarta へ** | decompose/decimate ディスパッチ | misarta | 実装は misarta 側にあり、articara 側は GeomData 変換のみ。fit 結果→(origin, shape) の変換を misarta::decompose に寄せれば mesh_ops はほぼ消滅 |
| **viz_feed → quadruped-gait feature** | Zenoh 受信 + GaitVizFrame 適用 | zenoh, quadruped-gait | 送信側(go2-gait-runner)と型を共有しており、受信ロジックも汎用。RobotModel への適用部だけ articara に残す |
| GUI(app/ + renderer)分離 | `articara-gui` | 全部 | 1-2b 完了後の最終形。急がない |

**推奨順**: legged-estimation → mesh_ops 吸収 → articara-rbd → articara-formats。
いずれも「まずモジュール境界をクレート境界品質にする → ディレクトリごと
`Cargo.toml` を与える」の2段階で、go2-gait-runner 分離(ccb0fe3)と同じ手順が使える。
