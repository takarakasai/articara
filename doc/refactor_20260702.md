## 4. 分割ロードマップ(2026-07-02 議論で改訂)

方針: **「マスタモデルの正は misarta」に寄せる**。当初の `articara-rbd` /
`articara-formats` 新設案は取り下げ(経緯は §4.4)。misarta には計算用
`Model<f64>` に加えて名前ベース・ロスレスの `native::MisaFile`(マスタ
スキーマ)が既にあり、編集操作の不変条件(rename 時の joint/mimic/
collision_pair/sensor/actuator/pose 追従更新)はスキーマ所有者の責務。
articara の `RobotModel` はマスタから **GUI ビューモデル**に降格する。

### 4.1 misarta へ吸収

| # | 対象 | 現在地 | 移動先・形 | 根拠 |
|---|---|---|---|---|
| A1 | 静的動力学解析(関節利用率、ペイロード容量) | rbd/dynamics.rs / dynamics.rs | `misarta::analysis`(仮) | 実装は既に `misarta::{rnea,crba,aba,centroidal}` 委譲。付加分は `Model` + `JointLimits` だけで書ける純数値 |
| A2 | 構造編集 API(add / remove / rename / re-root) | robot.rs | `misarta::native::edit`(仮)、`MisaFile` 上の操作 | 追従更新の不変条件は `.misa` スキーマの不変条件 |
| A3 | fit 結果 → shape 変換 | mesh_ops.rs | `misarta::decompose` に吸収 | アルゴリズム本体は既に misarta。articara 側は GeomData 変換の皮だけ |
| A4 | MJCF / USD パーサ | mjcf.rs / usd.rs / usd_import.rs | `misarta::mjcf` / `misarta::usd` | refactor_20260502 §7.3 の積み残し。A2 後は変換先が `MisaFile`/`Model` になる |
| A5 | SDF 二重実装の解消 | sdf.rs | `misarta::sdf` へ統合 | 同上 |
| A6 | メッシュローダ統一 + `MeshData` 正化 | robot.rs の `load_stl/obj/dae_mesh`、`resolve_package_path` | `misarta::MeshData` / `collada` / `native::mesh_load`(AssetSource)に委譲 | ロード・パス正規化・sanitize(20260502 §3.5)を misarta 一箇所へ。あわせて articara のビューモデルは **`Arc<MeshData>` を正、flat f32 配列は GL 用派生キャッシュ**に反転(材質/テクスチャ情報の喪失も解消)。**前提の misarta 側小改修**: `native::mesh_load` のディスパッチが stl/obj のみで `collada::load_dae` 未配線 |

### 4.3 articara に残るもの(GUI ビューモデル + 糊)

- `RobotModel` + rbd/model.rs — ロード済み flat 頂点メッシュ(未保存の
  V-HACD 結果含む)、解決済み color。構造操作は A2 へ委譲しキャッシュ再構築。
- rbd/misarta_bridge.rs — `MisartaCache`(a2m/m2a)とインタラクティブ IK
  (ピン・chicken-head 等 UI 都合)。
- format.rs `FormatRegistry` — 薄い UI ディスパッチ。中身が A4/A5 で
  misarta 呼び出しに変わる。
- collision.rs / primitives.rs / history.rs / gait.rs / isaac.rs —
  薄いアダプタ・レンダ都合・エディタポリシー・糊。
- app/ + renderer.rs + camera.rs、mujoco_sim.rs / wbc_pipeline.rs、
  scripting* — GUI・シム実行系・スクリプト層。
- GUI(app/ + renderer)の `articara-gui` 分離は 1-2b 完了後の最終形。急がない。

### 4.4 取り下げた案と経緯

`articara-rbd`(RobotModel + 編集 + 動力学の独立クレート)を当初提案したが、
検討の結果取り下げ。理由: (1) 静的動力学は既に misarta への薄いアダプタで、
独立させる実体がない。(2) 編集 API の自然な基盤は計算用 `Model` ではなく
misarta が既に持つ `native::MisaFile` であり、新クレートを挟むと
「マスタ表現の所有者」が二重になる。`articara-formats` も同根で、A4/A5
(misarta へ統合)に一本化。

### 4.5 移行順と運用規律

| 順 | 作業 | 規模感 | 前提 |
|---|---|---|---|
| 1 | A1 静的動力学の misarta 移動 | 小 | ✅ 済(misarta::analysis + 委譲、旧実装の符号バグ修正込み) |
| 2 | A6 メッシュローダ統一 + `MeshData` 正化 | 小〜中 | ✅ 済(A6a ローダ委譲 -435行、A6b `Arc<MeshData>` 正化。undo スナップショットのメッシュ深コピー解消) |
| 3 | A3 mesh_ops 吸収 | 小 | ✅ 済(misarta::decompose::decompose_mesh + articara は FitPart→GeomData の変換シムのみ) |
| 4 | B1 legged-estimation 切り出し | 中 | ✅ 済(linear_kalman + attitude_estimator + leg_odometry。LkfPipeline は MujocoSim 糊なので articara 残留) |
| 5 | A2 `native::edit` 実装 + articara 委譲化 | 中〜大 | robot.rs の I/O/編集分割(§3) |
| 6 | A4/A5 MJCF/USD/SDF の misarta 統合 | 大 | A2。`materialize_decomposed_meshes` / `MeshPathStyle` の URI 出力はエクスポータ都合なのでここに随伴 |
| 7 | B2 viz_feed 移動 | 小 | 任意 |

misarta の変更頻度が上がるため: 開発時は `[patch]` で sibling path を参照して
2リポ同時に回し、CI・他消費者は Cargo.lock のピンで固定する。
(P0-3 で踏んだ「misarta bump にテスト未追従で崩壊」がこの境界の失敗モード。
構造の正を misarta 一箇所に寄せることで、長期的にはズレの表面積を減らす。)
