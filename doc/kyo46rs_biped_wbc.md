# kyo46rs 二足 WBC: 現状と引き継ぎ

作成: 2026-07-31。**改訂: 2026-07-31(同日、§4 を全面差し替え)。**
対象リビジョン: articara@d5975e8+ + misarta@ef445f5(未push、`Cargo.toml` に
一時 patch) + kyo46rs_description@6895ddf。

> **改訂の理由。** 初版は「片足支持のボトルネックは `patch_contact` と足裏幅」
> と書いた。**これは誤りだった。** CoP 箱の飽和は原因ではなく症状で、真因は
> 最下位の力正則化が両足に**均等荷重**を目標として与えていたことである。
> これを直し、続けて出てきた二層も潰した結果、**片足立ちは 60 秒保持できる
> ようになった**(§4)。初版を読んで足裏を広げる作業に入らないこと。

`WbcPipeline` / `quadruped_gait::wbc` は 4 脚ハードコード(`[String; 4]`,
`LegId`)なので、二足は**その層を経由せず** misa-wbc のタスクカタログと
misarta の動力学を直接叩いている。実装は `examples/kyo46rs_com_squat.rs`。

## 0. TL;DR

- **屈伸は動く。** 重心深さ 70 mm まで、両足支持、degraded solve ゼロ。
- **片足立ちは立つ。** T=60 まで有界(roll −5.9〜−8.3°、立脚 fz 65.0 N =
  体重、遊脚 fz 0)。degraded 164→29、開ループ 705 ms→0、支持脚の膝の最小値
  11.3°→50.0°。**ただし 7〜8° 傾いた姿勢で、固定点ではなく緩やかに変動し
  続ける有界解**。「立つ」であって「直立静止」ではない。
- **CoP 箱の飽和は真因ではなかった。** 力正則化の均等荷重目標が CoP 予算を
  食い潰していた。修正すると箱の使用率は 0.99→0.42 以下に落ちる。**足裏
  98×38 mm は狭くない。** 足裏幅・立脚幅のモデル改修は現状の課題ではない。
- 作業の大半は「動いていたと思っていたものが動いていなかった」の訂正だった。
  §3 の罠一覧を先に読むこと。**T=8 や T=15 の SURVIVED は信用しないこと**
  ── 今回も T=15 生存 / T=25 転倒の偽陽性を踏んだ。

## 1. 動くもの / 動かないもの

| | 状態 | 数値 |
|---|---|---|
| 屈伸(両足支持) | **動く** | CoM 深さ 70 mm、tilt 0.097 rad、degraded 0 |
| 横方向の体重移動 | **動く**(深い屈伸が前提) | com_y 69.8/70.6 mm、足裏 -0.72° |
| 片足支持 | **立つ**(直立ではない) | 7〜8° 傾いた有界解。degraded 29、T=60 で発散せず |

再現:

```
cargo run --features mujoco --example kyo46rs_com_squat                    # 屈伸
AMP=0.07 cargo run --features mujoco --example kyo46rs_com_squat           # 深い屈伸
KNEE=1.10 HIP_PITCH=-0.55 ANKLE_PITCH=-0.55 LIFT=1 T=40 \
  cargo run --features mujoco --example kyo46rs_com_squat                  # 片足立ち
```

`KNEE` を変えるときは `HIP_PITCH = ANKLE_PITCH = -KNEE/2` を必ず併せて指定する
(和がゼロでないと足裏が床と平行にならず、縁接地になる)。

## 2. 定式化の要点

重心(CoM)を制御する。base の roll/pitch/height を個別に持つ旧版
(`kyo46rs_squat.rs`、比較用に残置)は姿勢タスクと高さタスクが同じ接触権限を
奪い合って頭打ちになる。base の 6 自由度は非駆動なので、バランスに効く唯一の
handle は接触レンチであり、屈伸は「CoM z の指令」でしかない ── 2 つのタスクを
1 つにできる。

タスク段(`levels`):

| 段 | 中身 |
|---|---|
| P0 | EoM + 接触(Baumgarte 付き)+ `patch_contact` + トルク箱 |
| P1 | CoM 加速度(3行) |
| P2 | トランク姿勢、**世界座標**の角ヤコビアン(2行) |
| P3 | 遊脚クリアランス(片足支持時のみ、**z の 1 行のみ**。§4.2) |
| P4 | 姿勢保持(16行、`POST=0` で無効化可) |
| P5 | τ→重力補償 + 接触力→公称配分 の正則化 |

### 触ると壊れるところ

- **接触拘束は Baumgarte 必須。** `zero_contact_acceleration` は
  `J·q̈ + J̇·v = 0`、つまり加速度しか拘束しない。足に角速度が付くと姿勢が
  等速でドリフトし、ソルバは「接触は満たされている」と言い続ける。左右対称な
  屈伸では露見しないが、横移動では**支持足裏が 19° まで転がった**。縁で立てば
  `patch_contact` の矩形 CoP 箱は床に無い領域を記述している。
- **`SOLE_CENTRE_X` / `SOLE_BELOW_FOOT_ORIGIN` / `sole_half_w` は URDF と
  一致必須。** CoP 箱の中心がずれる。片方だけ直すと静かに間違う。
- **armature / joint_damping は WBC 側に手で入れている。** misarta の動力学
  `Model` はロータ慣性を持たない(`armature` は MJCF 出力用フィールドで、
  プラントにしか届かない)。`M` の対角と `h` の速度項に加算している箇所を
  消すと、全駆動関節でモデルとシミュレータが食い違う。
- **`TRUNK_SIGN` は +1(教科書どおり)。** 過去に -1 が必要だった時期があるが、
  あれは misarta の `crba` バグ(§5)の補償であって規約の問題ではない。

## 3. 罠 ── 今日「成果」に見えて artifact だったもの

同じ穴に落ちないための一覧。**いずれも一度は本物だと報告してしまった。**

1. **自己干渉が支えになっていた。** 肩が y=±0.08 のとき前腕が股関節ブロックに
   埋まり、静止姿勢で 16 接触・37.2 kN(体重の 570 倍)が全 tick に存在した。
   片足立ちが「9 秒成立」したのはこれが突っ張り棒だったから。肩を ±0.115 に
   移動して解消。`kyo46rs_com_squat.rs` はスポーン姿勢で非地面接触があれば
   **assert で落ちる**。この assert を消さないこと。
   確認用: `cargo run --features mujoco --example kyo46rs_selfcollision_check`
2. **「SURVIVED」は「ループが total_t に到達した」の意味しかない。** 23° 傾いて
   落下中でも T=8 で切れば SURVIVED になる。T を延ばして再確認すること。
3. **バーンインが偶然に支配されていた。** 位置制御のみの二足は横方向に不安定で、
   その場整定では重心が -0.024〜-0.090 m のどこかに漂着し、生存が運で決まって
   いた。現在は**ベースを固定して関節だけ整定**させ、その姿勢から自由ベースで
   開始する。この分離を戻すと比較が全部コイントスになる。
4. **足幅の閾値はモデルを変えるたびに動いた。** 68→72→90 mm と動き、130 mm で
   逆に転倒(足同士が接触)。足幅は真因ではなかった。
5. **degraded solve のトルクを送ってはいけない。** misa-wbc の HoQp は内側 QP
   失敗時に `x_new = prev.x` を返し、level 0 ではそれが零ベクトル。つまり
   **同次方程式**の解 ── 重力 65 N を丸ごと落とし、接触 Baumgarte 行も一緒に
   捨てる。現在は直前の正常トルクを保持するが、**連続失敗時は開ループになる**
   ので 10 tick 連続で `[OPEN LOOP]` を印字する。この警告が出ている区間の
   数値は制御結果ではない。
6. **`level: 0` は「ハード拘束の衝突」ではない。** misa-wbc の null-space
   カスケードでは各不等式行が独自の slack を持ち、level 0 は何も継承しないので
   常に実行可能。あの status は Clarabel の数値失敗(条件数)である。
   トルク上限も関節端も binding していない。
7. **`Jc` の条件数は脚の特異点を検出できない。** 「片足化で Jc cond が
   32.5→2.1 に改善したから条件数は白」と一度結論したが、`Jc` は浮遊ベースを
   含む 6×nv で、ベースの 6 自由度が空間を自明に張るため脚の特異性は原理的に
   見えない。脚を見るには**脚単体の 6×6**(`kyo46rs_leg_conditioning`)を使う。
   そちらでは膝 63.4° の cond 38.6 に対し 11.3° で 206.3 と実際に悪化していた。
8. **動画の "QP: INFEASIBLE" は長らく `n_stance == 1` を表示していた。**
   ソルバ状態ではなく「片足かどうか」。片足になった瞬間から常時赤くなるので、
   degraded の証拠として読むと必ず間違える。現在は CSV の `degraded` 列
   (実 status)を読む。列が無い CSV では何も表示しない。
9. **ハンドオーバのブレンドは効かない。** フォールバック↔QP の切替段差が
   跳ねの原因だと考えて 10/20/40/80 tick のクロスフェードを試したが全て転倒
   (20 tick で膝が -25.8° まで過伸展)。段差は**制御器間ではなく、QP の壊れた
   解と復帰後の正常解の間**にある ── フォールバックを完全に無効化しても同じ
   離地が起きる。壊れた解に向かってフェードしても意味がない。`BLEND_TICKS`
   は既定 0 で残してある。
10. **偽陽性をまた踏んだ(罠 2 の再発)。** `KP_SWING=100` が T=8 と T=15 で
   SURVIVED を出したので改善と報告しかけたが、T=25 で転倒した。T=15 の時点で
   既に pitch +14.0°、CoM が支持多角形の外(101.9 mm / 限界 89.6 mm)にあった。
   **判定は必ず T=25 以上で行うこと。** 加えて、静的平衡に達したかどうかは
   「T を変えても数値が一致するか」で見る(既定設定は T=15 と T=25 が完全一致)。

## 4. 片足支持: 何が本当の原因だったか

**この節は全面改訂した。初版の「原因は `patch_contact`、ボトルネックは足裏幅」
は誤りである。**

### 4.1 真因 ── 力正則化が均等荷重を要求していた

最下位の力正則化はこう書かれていた。

```rust
forces_nominal[6 * slot + 5] = total_mass * G / nc as f64;   // 両足に均等
```

CoM タスクの零空間では「**足の間で荷重を移す**」と「**CoP を足の外側へ出す**」
が等価である。均等荷重を好む正則化が置かれていると、QP は後者を選び続ける。

静力学で検算すれば必要ないことがすぐ分かる。重心が y=+15 mm、足が ±70.6 mm に
あるなら、両足の CoP を中央に置いたまま荷重を 60.8/39.2 に配れば釣り合う。
ところが実測は:

```
 t     com_y |  fzL   fzR   L%  | copL_y  箱使用率
1.05    15.2 | 32.6  32.5  50.1 |   14.1  0.74     荷重は 50/50 のまま
1.20    20.0 | 33.2  31.8  51.1 |   17.8  0.94
1.35    25.2 | 35.7  29.3  54.9 |   17.9  0.94     以降ずっと飽和
```

**荷重移動を使わず CoP 移動だけで賄っている。** だから 70 mm の横移動のうち
最初の 20 mm で ±19 mm の箱を使い切り、片足遷移を余白ゼロで迎えていた。

正則化の目標を重心指令が示す荷重配分に合わせる(`LAT_SHARE=1`)と:

| | 均等荷重(初版) | 重心整合(修正) |
|---|---|---|
| 移動中の CoP 箱 最大使用率 | **0.99** | **0.17** |
| 荷重配分の追従 | 50%→86%(CoP 飽和後) | 50%→97.9%(重心に追従) |

**CoP 飽和は完全に消える。足裏 98×38 mm は狭くない。**

### 4.2 露出した二層と、その始末

飽和を取り除くと、それが隠していた破綻が順に出てきた。両方とも片付いた。

- **重心の横行き過ぎ。** CoM が立脚足(70.6 mm)を越えて 112.7 mm まで進み、
  支持多角形(〜89.6 mm)の外で倒れていた。`KD_COM` を 40→80 にすると最大
  70.2 mm と解消する。
- **離地直後のロール過渡。** 上を潰しても、遊脚が離れた 100 ms 後に roll が
  −2.5°→−5.7°、200 ms 後に −17.1° へ跳ね、fz が体重の 2 倍に達して倒れていた。

  **持ち上げ動作は原因ではない。** `LIFT_H=0.0`(持ち上げ指令を外し接触だけ
  切る)でも同じく転倒し、peak fz も 206.6 N で完全に一致する。

  原因は遊脚タスクが**世界座標の x,y も硬く拘束していた**こと。目標は
  `swing_home`(初回 tick で凍結した位置)で、胴体を 70 mm 横移動させながら
  遊脚だけ元の場所に留めろという指令になっていた。それを保持する反力が立脚に
  落ちる。このタスクの目的は本来クリアランスだけである。`SWING_ZONLY=1` で
  z 行のみに落とすと解消する。

### 4.3 現状 ── 60 秒の片足立ち

**上の 3 点(荷重配分・CoM 減衰・遊脚 z のみ)を全て入れると片足で立つ。**
2026-07-31 時点でこれが既定。

```
KNEE=1.10 HIP_PITCH=-0.55 ANKLE_PITCH=-0.55 LIFT=1 T=40 \
  cargo run --features mujoco --example kyo46rs_com_squat
```

T=60 まで回した結果:

```
   t    roll°   pitch°    comy     fzL  CoP箱使用率
 6.0    -5.94     0.46   46.58   65.05   0.420
18.0    -8.18    -4.99   46.52   65.04   0.360
36.0    -7.98    -4.94   46.67   65.05   0.379
54.0    -7.81    -3.10   47.82   64.99   0.378
```

roll −5.9〜−8.3°、pitch −5.0〜+0.7°、CoM y 46.5〜49.4 mm、立脚 fz は
65.0 N(体重ちょうど)で一定、遊脚 fz は 0。すべて**有界**で発散しない。
degraded 29 は全て遷移前後に集中し、以後ゼロ。

その後 §4.5 のアンカー修正を入れて、roll −3.58〜−3.90°、最大傾き 0.146 rad、
CoM y 57.0 mm で 60 s 一定まで改善した。以下の表の「現在」はその値。

改善の内訳:

| | 初版 | 中間 | **現在** |
|---|---|---|---|
| degraded | 164 | 73 | 46 |
| 最大傾き | 0.197 rad | 0.199 rad | **0.146 rad** |
| 整定 roll | ─ | −7〜−8° | **−3.8°** |
| 移動中の CoP 箱使用率 | 0.99 | 0.99 | **≤0.42** |
| 支持脚の膝 最小 | 11.3° | 48.2° | **50.0°** |
| 開ループ | 705 ms | 0 | 0 |
| QP と実測の接線力差 | ─ | +22.4 N | **+8.5 N** |
| 検証 | ─ | T=25 静的一致 | **T=60 有界** |

**ただし固定点ではない。** 既定設定は T=15/T=25 で数値が完全一致する静的平衡
だったが、現在の設定は緩やかな変動を続ける有界解である(60 s で roll が
−5.9〜−8.3° の範囲を往復)。倒れないことは確認したが「静止している」とは
書けない。また 7〜8° 傾いた姿勢であって直立ではない。

なお **`UNLOAD_RAMP` は 0 が既定に戻っている。** 荷重配分が正しくなれば
ランプは不要で、むしろ `LAT_SHARE=1` と併用すると CoP 使用率が 1.00 に
戻ってしまう(ランプが荷重目標と衝突する)。

### 4.5 QP の想定接触力と実接触力のずれ

**この節の計測は、他の全ての結論を汚染しうる種類のものである。** crba のバグを
見つけたのと同じ手口 ── 同じ量を独立な 2 系統で測って突き合わせる ── で、
接触力にも系統的なずれが見つかった。

整定した片足姿勢(静止、degraded なし)での実測:

| | fx | fy | fz | \|ft\| |
|---|---|---|---|---|
| QP の想定 | +4.7 | **+23.7** | 71.3 | **24.2 N** |
| MuJoCo 実測 | −0.0 | −0.0 | **65.1** | **0.0 N** |

静止体なので真値は `(0, 0, mg)` 以外あり得ず、65.1 N は体重
(6.64 kg × 9.81)と一致する。**QP は体重の 37% に当たる横力を出している
つもりで、実際には出ていない。** 送っているトルクは存在しない反力を前提に
計算されている。

原因は**接触アンカーの陳腐化**。アンカーは初回 tick で凍結され、その後
立脚足は 11.65 mm 移動する(接触パッチは 24.0 mm)。残った 12 mm の誤差が
`kp_c × 0.0122 = 19.6 m/s²` の横加速度を要求し続け、QP はそれを実現する
横力を計画する。

対処は `ANCHOR_LEAK`(既定 0.2 /s)で、アンカーを足の実位置へ緩やかに追従
させる。**並進のみである。** 回転まで追従させると Baumgarte 本来のドリフト
除去(§2「触ると壊れるところ」、放置すると足裏が 19° 転がる)が死んで全滅する。
`ANCHOR_LEAK_ROT` は既定 0 のまま置いてある。

効果: 接線力差 22.4→8.5 N、法線力差 7.4→2.4 N、整定 roll −7〜−8° → −3.8°、
最大傾き 0.169→0.146 rad。degraded は 28→46 と増える(トレードオフ)。

**残差 8.5 N は消えていない。** QP は依然として体重の 13% の横力を想定して
いる。アンカーだけが原因ではない。

**ゲインは極めて敏感で、動作点が失敗領域に隣接している。**
0.2 生存 / **0.3 転倒** / 0.5 生存 / 2.0 転倒 と非単調。罠 4 と同じパターンで、
モデルを触れば必ず再調整が要る。

#### 摩擦について測ったこと(いずれも直感に反する)

- **滑りと degraded は無関係。** 荷重をかけた状態(fz>20 N)で摩擦錐使用率
  0.6 超の 24 tick のうち degraded は **1 つだけ**。滑りは QP が Optimal を
  返している最中に起きる。「フォールバックが錐を無視している」という見立ては
  誤りだった。
- **地面摩擦を上げると悪化する。** μ 0.7(既定)で生存、1.5 と 3.0 では転倒。
  滑りは単なる欠陥ではなく、遷移のエネルギーを逃がすコンプライアンスとして
  働いている。**現在の成功は足が少し滑ることに部分的に依存している。**
  μ を上げて「綺麗にする」方向へ進まないこと。

### 4.4 次の一手

1. **残差 8.5 N を追う(最優先)。** §4.5 のずれはトルク指令そのものを汚す。
   他のどのチューニングも、この上に載っている限り信用度が落ちる。
2. **遷移時の degraded 46 を消す。** 全て離地前後に集中している。CoP には
   余白があるので、初版のような「箱が足りない」話ではない。
3. **`patch_contact` と足裏幅を疑う作業は不要。** §4.1 で無罪が確定した。
4. **動作実績のあるモデルでの検証を検討中。** kyo46rs は概念モデルで、慣性・
   アクチュエータ配置・可動域のいずれも実機の裏付けがない。今回見つかった
   「狭いゲイン窓」「非単調な閾値」「モデルとプラントの力の不一致」が制御則の
   問題なのかモデルの問題なのかを、この機体だけでは切り分けられない。

## 6. モデル側の宿題(レビュー由来、未着手)

多視点レビュー(38 件提起 → 11 件が反証検証を通過)で残ったもの。

- **hip_pitch ブースターのベルトが 2 つの回転関節を跨いでいる。** トルソ内
  (0,±0.045,−0.055) から hip_pitch 軸 (0,±0.07,−0.201) までの間に hip_yaw
  (z 軸)と hip_roll(x 軸)がある。ベルトでは通せない。`hip_roll_link` へ
  移すのが解で、近位なので遊脚慣性のペナルティはゼロ。膝側は同一リンク内で
  0 関節跨ぎなので正当。
- **README の寸法導出が全て古い。** 全高は 0.661 m ではなく **0.684 m**、
  L_leg は 0.301 ではなく **0.293 m**。関節間隔も 30 mm と書いてあるが実際は
  45/46/46。トルク表は一律 2.7% 過大(定性的な結論は変わらない)。導出を
  `scripts/` のスクリプトにして二度とドリフトさせないのが望ましい。
- **ankle_roll の可動域が余裕なし。** 足裏を平らに保つだけで ±20° の 82%
  (16.5°)を使う。横傾き `atan(70/325)=12.2°` + バランス制御分。歩行では
  横揺れが増えるので広げる検討価値がある。
- **モデルに無いもの:** 関節 Coulomb 摩擦、バックラッシュ、ベルトの
  コンプライアンス。MuJoCo の `solref`/`solimp`/`condim` は未設定(既定値)。

### アクチュエータ選定について測ったこと

`hip_pitch` の 2 基目は、測る限りどの負荷ケースでも不要:

| 負荷ケース | 測定方法 | hip_pitch |
|---|---|---|
| 50 mm 屈伸・定常 | WBC 実機、degraded 0 | 0.41 N·m |
| CoP 限界まで前傾 | WBC 実機、degraded 0 | 0.20 N·m |
| 遊脚 2.0 Hz ±0.45 rad | 逆動力学 | 1.68 N·m |

いずれも EL05 1 基の連続定格 1.8 N·m 以内(最悪でも 93%、ピーク比 28%)。
前傾させても負荷は**足首**に行き(0.10→1.36 N·m)hip_pitch はほぼ動かない ──
`k·M·g·L` は脚全体の概算で、どの関節に載るかは言っていない。
一方 **膝の 2 基は正当**(屈伸で 2.04 N·m、1 基なら連続定格の 113%)。
外せば 0.484 kg(全備の 7.3%)減、しかも大腿から減るので遊脚慣性も下がる。
ただし支持脚の hip_pitch だけは片足支持が必要で未測定。

## 7. 補助リグと診断スイッチ

| example | 用途 |
|---|---|
| `kyo46rs_com_squat` | 本体(屈伸 / 片足立ち) |
| `kyo46rs_selfcollision_check` | 自己干渉の有無 |
| `kyo46rs_convention_check` | misarta vs MuJoCo(重力・質量行列・qacc) |
| `kyo46rs_stand_check` | WBC 無し、プラント単体 |
| `kyo46rs_leg_conditioning` | 脚ヤコビアンの条件数 vs 膝角 |
| `kyo46rs_swing_torque` | 逆動力学でのアクチュエータ選定 |
| `kyo46rs_squat` | 旧 base 座標版(比較用) |

主な環境変数: `AMP`(屈伸深さ)、`LIFT`(片足モード)、`KNEE`/`HIP_PITCH`/
`ANKLE_PITCH`(初期姿勢)、`NO_PATCH`(`patch_contact` 無効)、`COP_FRAC`、
`TORQUE_SCALE`、`CONDCHK`/`COMCHK`/`VELCHK`/`COLCHK`(各種検証出力)、
`TRAJ_CSV`(軌跡ログ)。

片足遷移まわりで後から入れたもの:

| 変数 | 既定 | 意味 |
|---|---|---|
| `LAT_SHARE` | **1** | 力正則化の荷重目標を重心指令に整合(§4.1)。0 で旧挙動 |
| `UNLOAD_RAMP` | **0** | 遊脚を外す前に力上限を落とす秒数。`LAT_SHARE=1` とは併用しないこと(CoP 使用率が 1.00 に戻る) |
| `SWING_ZONLY` | **1** | 遊脚拘束を z のみに。0 で世界座標 x,y も拘束(§4.2 の転倒要因) |
| `KD_COM` | **80** | CoM 減衰。40 だと横に行き過ぎて支持多角形を外れる |
| `HOLD_KP`/`HOLD_KD` | 15 / 2 | degraded 時フォールバックの姿勢 PD。**狭い**。KP≥20 で転倒 |
| `HOLD_BRIDGE` | 8 | フォールバックへ切り替えるまで凍結で橋渡しする tick 数 |
| `HOLD_LAST` | 0 | 1 で旧挙動(常に直前トルク凍結)。A/B 用 |
| `BLEND_TICKS` | **0** | 切替クロスフェード。効かないことが確認済み(罠 9) |
| `ANCHOR_LEAK` | **0.2** | 接触アンカーが足の実位置へ追従する速さ(1/s)、**並進のみ**。0.3 で転倒する(§4.5) |
| `ANCHOR_LEAK_ROT` | **0** | 同、回転。上げると Baumgarte のドリフト除去が死ぬ |
| `MU_GROUND` | 0.7 | プラント側摩擦。QP の `FRICTION_MU`(0.6)とは別物。上げると転倒する |
| `COPCHK` | 0 | CoP と箱使用率を毎 tick 印字 |

`TRAJ_CSV` には `degraded`(実 status)のほか、足ごとに **CoP・接触力・摩擦錐
使用率・接触パッチの世界位置**を出力する。CoP と接触力は QP の解が含意する値と
MuJoCo の実接触から求めた値の **2 系統**あり(`fqp_*` / `fmj_*`)、これを突き
合わせて §4.5 のずれを見つけた。両者は二重支持中は
1 mm 以内で一致し、**解が壊れたところだけ乖離する**(QP 側が fz=0 に落ちる)。
crba のバグを見つけたのと同じ手口で、片方だけ見ていると必ず騙される。

動画は `examples/render_com_squat_video.py <traj.csv> <out.mp4>`。URDF の
プリミティブを numpy + PIL で自前ラスタライズする(mujoco の Python
バインディングは使わない)。メイン視点に加えて**正面図**と**足裏を上から見た
CoP パネル**(箱の枠・QP 想定・MuJoCo 実測・軌跡)を右列に出す ── 横方向の
体重移動はメインカメラでは真横から見えないため。`COMPACT=1 VID_W=640` で
並列比較用の狭いフレーム、`ANKLE_CLOSEUP=1` で足首の寄り。

### プラント側の制約

- **`SIM_DT = 1 ms` は必須。** `MujocoSim` の関節 PD は陽的な速度帰還で、
  `actuator_kv < 2·I/dt` でしか安定しない。遠位のロール関節は
  `I ≈ 6e-4 kg·m²` なので 2 ms では `kv` 上限が 0.63 ── 位置保持に使いたい値を
  下回る。実測(`kyo46rs_stand_check`、WBC 無し): 2 ms は t=0.65 で崩壊、
  1 ms / 0.5 ms / 0.25 ms は同一パラメータで 5 秒立つ。
