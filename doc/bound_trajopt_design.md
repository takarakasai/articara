## 1. 問題設定と背景(なぜ trajopt か)

§5f の到達点と壁:
- **達成**: Poincaréデッドビート足配置で恒久安定(83周期)・本物の
  対空(10-22cm)のエネルギッシュBoundを実現(§5f6)。ただし**その場〜
  後退**。
- **壁**: 7手法(rate-deadbeat / 絶対placement / 速度regulator /
  touch_down分離 / F_x推進90N / HZD軌道相対 / DC-blocker)すべてで
  後退が覆らない。決定的観測は **k_rate=0 のトリム単独ですら vx≈0**
  ——**前進速度追従そのものがエネルギッシュ構成(duty=0.34)で破綻**
  (§5bi の bound速度天井と同根)。姿勢安定化はその上に後退を上乗せ
  しているだけ。

**なぜ既存MPCで前進しないか(仮説)**: 現行 FullCentroidal MPC は
**受動的な平坦参照**(一定速度・pitch=0・一定高さ)を短い受信ホライズン
で追う。エネルギッシュBoundは滞空・大pitch揺動を伴う**非自明な周期
軌道**であり、平坦参照はその軌道と両立しない。MPCは各tickで「平坦参照へ
戻そう」とし、滞空/pitch揺動という軌道本来の動きと競合して前進推力を
食い潰す。**足りないのは「前進するエネルギッシュBoundの、実行可能な
周期軌道そのもの」**。

**trajopt の役割**: 前進する全身周期軌道(base pose/twist・GRF・
foothold・関節q の時間発展)をオフラインで一度解き、それを MPC/WBC の
**参照**として与える。参照が前進する nominal 軌道を供給し、デッドビート
(§5f6、既実装)が偏差を安定化する。§5f8 の「軌道相対デッドビート」は
まさにこの参照追従を前提にした機構——**良い参照が無かった**のが前進
できなかった真因。

## 2. 全体アーキテクチャ(2段構成)

```
[オフライン] 周期軌道 trajopt (TOWR流 SRBD+foothold+timing NLP)
     │  前進エネルギッシュBoundの1周期を解く(周期境界条件)
     ▼
  参照軌道テーブル: t → (base pose/twist, GRF×4, foothold×4, 関節q)
     │
[オンライン] 既存 WBC/FullCentroidal MPC が参照を追従
     │  + Poincaréデッドビート足配置(§5f6実装済)で偏差安定化
     ▼
  前進する安定エネルギッシュBound
```

- **段1(新規)**: 周期軌道生成器。1周期分の SRBD trajopt。多日規模の
  新サブシステム。
- **段2(既存流用)**: MPC/WBC の参照を平坦から段1の軌道に差し替える。
  参照供給の配線 + デッドビート(実装済)。比較的軽い。

## 3. 段1: 周期軌道 trajopt の定式化

TOWR (Winkler et al. RA-L 2018, phase-based end-effector param) の
考え方を SRBD で。四足Boundは接地系列が既知(前ペア↔後ペア、間に滞空)
なので、**接触スケジュールは固定**でよい(contact-implicit の相補性
制約を避けられ、NLPが素直になる)。

### 決定変数(1周期 [0,T])
- ベース: 位置 `p(t)∈R³`、姿勢 `θ(t)`(roll/pitch/yaw)、
  速度 `v(t)`、角速度 `ω(t)`。時間離散化 N ノード。
- 各脚 i: foothold `r_i`(接地中は固定、遊脚は自由)、
  GRF `f_i(t)∈R³`(接地中のみ非ゼロ)。
- (任意) 位相タイミング `T_stance, T_flight`(まずは固定、後で自由化)。

### ダイナミクス(SRBD, §full_centroidal_mpc.rs と同一モデル)
```
m·v̇ = Σ_i f_i − m·g
d/dt(I·ω) = Σ_i (r_i − p) × f_i
ṗ = v,  θ̇ = E(θ)·ω
```
滞空区間は Σf_i=0(全脚遊脚)→ 自由落下+自由回転(§5f の弾道解と一致)。

### 制約
1. **周期境界**: `x(T) = x(0)` を**前進分だけシフトして**課す:
   `p(T) = p(0) + [v_x·T, 0, 0]`、それ以外の状態(θ,v,ω,高さ)は
   `x(T)=x(0)`。← これが「前進する周期軌道」の核。
2. **前進速度**: 平均 `(p_x(T)−p_x(0))/T = v_x_target`(例 1.0 m/s)。
3. **接地相補**(固定スケジュールなら): 接地脚は `f_iz ≥ 0`・
   足位置 z=0・水平滑りなし; 遊脚は `f_i=0`・swing軌道(滞空高さ)。
4. **摩擦錐**: `|f_ixy| ≤ μ·f_iz`(既存 friction_cone と同形)。
5. **運動学到達性**: foothold がベースから届く範囲(TOWR の
   reachability box)。ラフには hip 中心の箱制約。
6. **滞空**: flight 区間で全 f_i=0、ベースは弾道。
7. (任意)関節/トルク限界: 全身版にするなら。まず SRBD+到達性で可。

### コスト
- 前進速度追従(制約で課すなら軽く)、GRF/effort 最小化、pitch/roll
  揺動の正則化(過大な宙返り抑制)、滑らかさ。

### ソルバ
- NLP。既存 `full_centroidal_mpc.rs` は SRBD ダイナミクスの解析微分と
  SQP を既に持つ——**その微分/残差コードを流用**し、受信ホライズンを
  「1周期+周期境界条件」に置き換えるのが最短。ipopt 等の外部依存を
  避けられるなら自前 SQP を周期問題に拡張。
- まずは**接触固定・SRBD・到達性箱**の軽量版で解を出し、段2で回るか
  検証してから全身/自由タイミングに拡張。

## 4. 段2: オンライン追従(既存流用)

1. 段1の軌道を時間テーブル(または位相→状態)で保持。
2. MPC/WBC の**参照ループ**(`full_centroidal_controller.rs` の
   `ref_states`/`ref_inputs` 構築、L1256付近)を、平坦参照から段1軌道の
   位相サンプルに差し替える。トリム参照(`bound_trim`)が既に
   「位相→pitch/GRF」を供給する構造なので、**トリムを段1軌道テーブルに
   一般化**するのが自然な差し込み口。
3. **デッドビート(実装済 §5f6/5f8)** をそのまま偏差安定化に使う。
   参照が前進軌道になるので、§5f8 の軌道相対デッドビートが本来の意図
   通り機能する見込み(後退DC配置が消える)。
4. 段1の foothold 系列を MPC の foothold 参照にも供給。

- **周期軌道の存在性**: 前進エネルギッシュBoundの実行可能周期軌道が

## 付録A: P0 存在性確認の結果(2026-07-26, 実施済)

`ref/scripts/bound_trajopt_p0_shooting.py`(単一シューティング、平面SRBD、
scipy least_squares、周期性=硬制約・摩擦/fz≥0/到達性/pitch有界=強ペナルティ)。

**結果 — 前進する物理的に実行可能な周期Bound軌道が存在**:
```
周期性+前進残差 1.2e-7 / avg vx = 1.000 m/s(目標達成)
pitch peak 0.161 rad(有界・宙返りせず)
reachability 0.128 m(箱0.16内)/ 摩擦マージン −0.000(錐境界=充足)
z_range 0.040 m(4cmの本物の上下動)/ vz [−0.67,+0.58] m/s
```
(注: collocation NLP 版 `bound_trajopt_p0_existence.py` は scipy の
有限差分ソルバには重すぎたため、シューティングに切替。ペナルティ無しの
初回解は数学的に周期的だが物理破綻(pitch 2.7rad・fz負・摩擦4倍)——
摩擦/fz≥0/到達性/pitch有界を強ペナルティで課して物理解に到達した。)

**含意**: **§5f で前進しなかった真因は「この前進周期軌道が参照として
与えられていなかった」こと**と裏付けられた。前進Bound軌道は Go2 の
質量/慣性/μ で確かに存在し、pitch有界・足到達可能・摩擦充足。既存WBCは
両立しない平坦参照を追っていた。**trajopt計画(§2の2段構成)の前提が
実証的に確定**——次段(P1: 段1ソルバを Rust で、または P2: この平面
軌道を参照に段2差し込み)に進む価値がある。

**留保**: 平面SRBD(roll無し・全身運動学/トルク限界無し)。滞空は
duty=0.34 で控えめ(4cm/0.048s)、大対空は低dutyで再確認要。摩擦
マージン≈0(錐ギリギリ)なので実trajoptでは余裕を持たせる。

## 付録B: P2 実装と結果(2026-07-26, 実施済)

段2(既存WBC/MPC の参照ループを P0 の前進軌道に差し替え)を実装:
- コントローラに**表形式参照注入**機構(`bound_tabulated_reference`、
  位相補間で z/pitch/vx/vz/ω を各horizon stepの参照に投入)。q_diag より
  base_pos.z は重み50で追従、v_com は重み1、pitch 重み25。
- P0軌道を48行CSVにエクスポート(`bound_p0_orbit.csv`)、テストで読込。
- generator/gait/ハーネス配線、デッドビート併用。

**結果(duty=0.34, cmd_vx=1.0, 12s、多構成スイープ)**:

| 構成 | 安定 | 前進 |
|---|---|---|
| 参照のみ(deadbeat無) | t=3s転倒 | 初期のみ前進、vx≈0 |
| 参照 + 絶対deadbeat | **安定(12s)** | 後退 −0.5 |
| 参照 + orbit-relative deadbeat(表nominal) | t=5s転倒 | — |
| 参照 + 絶対deadbeat + DC-block(0.4-1.5) | 安定 | 後退 −0.5(DC-block効かず) |
| 参照 + base_pos.x重み + 状態重み(placement無) | t=4-8s転倒 | vx≈0(前進せず) |

**P2の決定的所見(ジレンマの完全な明確化)**:
1. **前進参照は前進を引く**(初期1秒 vx +0.1〜+0.2、§5f8平坦参照 vx≈0 と
   対照的)——参照差し替えの効果は確認。
2. しかし**MPCが前進速度 vx=1.0 を追従できない**(定常で後退/≈0)。
   base_pos.x 重みを80まで上げても前進せず。§5bi の bound速度天井と同根。
3. **安定化 と 前進 が両立しない**:
   - placement deadbeat = 恒久安定を与えるが**運動学的に後退ドラッグ**。
   - placement無し(状態重みのみ)= 後退しないが**pitch を保てず転倒**。
   - 前進参照も DC-block も base_pos重みも、この二律背反を破れない。
4. **表nominalの orbit-relative deadbeat は逆効果**(平面SRBD nominal ≠
   実3D Go2 pitch_rate のモデル不一致で偏差が汚れ、安定化作用喪失→転倒)。

**結論**: **段2(既存追従スタックで P0参照を追う)だけでは前進安定
エネルギッシュBoundに届かない**。既存の安定化機構が各々致命的欠陥を持つ
(placement=後退、状態重み=転倒)ため。真の解には **P1/P3**——**全身
周期軌道を設計し、安定化(足配置)を軌道の一部として同時最適化し
(後退を生まない)、GRF追従も密にする**専用追従器——が必要。P2は
「前進参照は有効だが既存追従器では不十分」を実証し、P1 の必要性を確定した。

**残る committable 実装**: 表参照注入機構(`set_bound_tabulated_reference`)、
デッドビート足配置(§5f6)、orbit-relative/DC-blocker(§5f8)は全て
既定offのオプトラインで残置、P1/P3 の部品として再利用可能。
